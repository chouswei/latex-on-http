# endleaf-pdfcheck (prototype, ENDLEAF-R81)

A Rust port of the warn-only PDF layout checker `colophon/pdf_layout_check.py`, written to
time against the Python version on the ARM worker host. It is a measurement prototype, not
a production replacement: the worker still runs the Python checker.

## Build

    CARGO_TARGET_DIR=... CARGO_INCREMENTAL=0 cargo build --release

Needs Rust 1.85 or newer (`rust-version = "1.85"`; `Cargo.lock` is committed and was
resolved MSRV-aware). The release profile is `opt-level=3`, fat LTO, one codegen unit,
`panic="abort"`, stripped; the binary links glibc dynamically. Dependencies (all
MIT/Apache-2.0): `miniz_oxide` (Flate), `regex`, `unicode-normalization` (NFKC),
`serde_json`. The PDF parser, content-stream lexer, fonts, geometry (convex clipping,
Liang–Barsky / Cyrus–Beck line clipping, point-in-polygon), the box grid and the kd-tree
are own code; no AGPL PDF library is used.

## Use

    endleaf-pdfcheck [--page-budget SEC] [--doc-budget SEC] [--template ID]
                     [--blocks FILE.json] [--tex-pages N,N] [--repeat N] [--timing]
                     [--dump] PDF...

- Budgets default to 0.25 s per page and 2.0 s per document, with the Python `_Budget`
  semantics (page clock reset at each page, document clock from the start, an overrun
  stops the run, keeps the findings so far and adds one `pdf_check_skipped` note).
- `--blocks` is a JSON object `{"1": [left, top, width, height], ...}` in TeX pt (the
  `ENDLEAF_PAGEBLOCK` values); `--tex-pages` are the pages TeX already names (OD-PDF-4).
- Output: one JSON line per PDF:
  `{"file", "pages", "sec", "page_sec": [...], "items": [...], "log": [...]}`. `items`
  have the Python `item_for` / `check_pdf` shape. With `--repeat N` the check runs N times
  in-process on the same bytes and `runs_sec` lists each run (`sec` is the first, cold run).
- `--timing` prints a per-file summary (cold, warm median, per page, slowest page) to stderr.
- `--dump` prints, per page, the glyph, word, line and path counts and each line's text and
  box instead of findings (the parity dump; see `scripts/py_dump.py`).

## Layout

- `src/pdf.rs` objects, pdfminer-compatible lexer and content parser, xref/object streams,
  fallback scan, filters.
- `src/font.rs` simple, Type 3 and CID fonts: widths, descent, ToUnicode, encodings,
  embedded Type 1 encodings, base-14 metrics, Adobe-Japan1.
- `src/extract.rs` the interpreter and device (`extract_pages`): glyph quads, paths,
  images, Form XObjects, off-page glyphs.
- `src/check.rs` grouping (`_link`, words, lines, Docstrum guard, glyph runs, folio),
  figure regions, the eight checks, `dedupe`, items, budget.
- `src/geom.rs` geometry; `src/tests.rs` unit tests.
- `src/tables.rs`, `src/japan1.bin` generated by `scripts/gen_tables.py` from the pinned
  pdfminer.six data (MIT; glyph list, latin encodings, base-14 AFM widths from the Adobe
  AFM files, the Adobe-Japan1 map from the Adobe CMap resources, BSD-3-Clause).
- `scripts/` parity tools: `compare.py`, `py_dump.py`, `compare_dump.py`, `synth_cases.py`,
  `run_parity.sh`. See `PARITY.md` for results and known deviations.

`src/tables.rs` is run through `cargo fmt` after `scripts/gen_tables.py` writes it.
`cargo fmt --check` and `cargo clippy --release -- -D warnings` are clean on Rust 1.100.
