# endleaf-pdfcheck (ENDLEAF-R82)

The warn-only PDF layout checker of the Endleaf render worker (ENDLEAF-R81), in Rust. The
worker image builds it from this directory (`container/Dockerfile.endleaf`, a
`rust:bookworm` builder stage, `cargo build --release --locked`) and installs it as
`/usr/local/bin/endleaf-pdfcheck`; `colophon/sandbox_render.py` runs it after the final TeX
pass of every PDF job (ENDLEAF-R82-IFACE).

`colophon/pdf_layout_check.py` is the reference implementation (oracle). It is kept in the
repository for tests and CI only and is not installed or run in the worker image; its
pinned wheels are `tests/requirements-pdfcheck-oracle.txt`.
`tests/colophon/test_pdfcheck_parity_r82.py` (CI job `pdfcheck-parity`) runs every corpus
PDF and real sample through both and fails on any difference outside the allow-list of
deliberate deviations in `PARITY.md`.

## Build

    CARGO_TARGET_DIR=... CARGO_INCREMENTAL=0 cargo build --release

Needs Rust 1.85 or newer (`rust-version = "1.85"`; `Cargo.lock` is committed and was
resolved MSRV-aware). The release profile is `opt-level=3`, fat LTO, one codegen unit,
`panic="abort"`, stripped; the binary links glibc dynamically. Dependencies (all
MIT/Apache-2.0): `miniz_oxide` (Flate), `regex`, `unicode-normalization` (NFKC),
`serde_json`. The PDF parser, content-stream lexer, fonts, geometry (convex clipping,
Liang–Barsky / Cyrus–Beck line clipping, point-in-polygon), the box grid and the kd-tree
are own code; no AGPL PDF library is used.

## Use

Worker mode (ENDLEAF-R82-IFACE), one PDF:

    endleaf-pdfcheck --sidecar SIDECAR.json FILE.pdf

- The sidecar is one JSON object `{templateId, blocks, marks, shellPages, texPages}`:
  `blocks` `{"1": [left, top, width, height], ...}` in TeX pt; `marks` rows
  `[id, tag, page, yFromBottomPt, orientation]` (fulldoc only); `shellPages`
  `{"<fenceNumber>": page, ...}`; `texPages` `[page, ...]`. Keys are decimal strings;
  missing fields are empty and unknown keys are ignored.
- stdout is exactly one `{"items": [...], "log": [...]}` object (`sec` and `page_sec` only
  with `--timing`); diagnostics go to stderr. Items carry `partId` (from `marks`, as
  `part_for`) and `fenceNumber` (from `shellPages`) exactly as `item_for` adds them.
- Exit 0 also when there are findings, `pdf_more_findings` or `pdf_check_skipped` notes
  (an encrypted PDF gives one note, `pdf layout check stopped (encrypted) before pg1`);
  exit 2 on a usage error (bad flag, bad sidecar, not exactly one PDF, or `--sidecar`
  mixed with `--template`, `--blocks`, `--tex-pages`, `--dump` or `--repeat`).
- `--version` prints `endleaf-pdfcheck <crate version>` and exits 0.

Parity and timing mode (the R81 flags), any number of PDFs:

    endleaf-pdfcheck [--page-budget SEC] [--doc-budget SEC] [--template ID]
                     [--blocks FILE.json] [--tex-pages N,N] [--repeat N] [--timing]
                     [--dump] PDF...

- Budgets default to 0.25 s per page and 2.0 s per document, with the Python `_Budget`
  semantics (page clock reset at each page, document clock from the start, an overrun
  stops the run, keeps the findings so far and adds one `pdf_check_skipped` note).
- `--blocks` is a JSON object `{"1": [left, top, width, height], ...}` in TeX pt (the
  `ENDLEAF_PAGEBLOCK` values); `--tex-pages` are the pages TeX already names (OD-PDF-4).
- Output (without `--sidecar`): one JSON line per PDF:
  `{"file", "pages", "sec", "page_sec": [...], "items": [...], "log": [...]}`. `items`
  have the Python `item_for` / `check_pdf` shape. With `--repeat N` the check runs N times
  in-process on the same bytes and `runs_sec` lists each run (`sec` is the first, cold run).
- `--timing` prints a per-file summary (cold, warm median, per page, slowest page) to stderr.
- `--dump` prints, per page, the glyph, word, line and path counts and each line's text and
  box instead of findings (the parity dump; see `scripts/py_dump.py`).

## Layout

- `src/pdf.rs` objects, pdfminer-compatible lexer and content parser, xref/object streams,
  fallback scan, filters.
- `src/font.rs` simple, Type 3 and CID fonts: widths, descent, ToUnicode, encodings,
  embedded Type 1 encodings, base-14 metrics, predefined CMaps, the TrueType cmap fallback.
- `src/extract.rs` the interpreter and device (`extract_pages`): glyph quads, paths,
  images, Form XObjects, off-page glyphs.
- `src/check.rs` grouping (`_link`, words, lines, Docstrum guard, glyph runs, folio),
  figure regions, the eight checks, `dedupe`, items, budget.
- `src/geom.rs` geometry; `src/tests.rs` unit tests.
- `src/tables.rs` generated by `scripts/gen_tables.py` from the pinned pdfminer.six data
  (MIT; glyph list, latin encodings, base-14 AFM widths from the Adobe AFM files).
- `src/cmapdata/` generated by `scripts/gen_cmaps.py`: the predefined CMaps and the four
  CID -> Unicode maps (Adobe cmap-resources, BSD-3-Clause, as pdfminer.six ships them).
- `corpus.txt` the 21 repository PDFs of the parity corpus.
- `tests/` gap and regression cases (`gap_n2.rs` .. `gap_n5.rs`, `fixtures/gap/`).
- `scripts/` parity tools: `compare.py`, `py_dump.py`, `compare_dump.py`, `synth_cases.py`,
  `run_parity.sh`, `make_gap_fixtures.py`. See `PARITY.md` for results and known deviations.

`src/tables.rs` is run through `cargo fmt` after `scripts/gen_tables.py` writes it.
`cargo fmt --check` and `cargo clippy --release -- -D warnings` are clean on Rust 1.100.
